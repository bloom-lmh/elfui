# ElfUI v0.1.0-beta.10 响应式 Prop 整体替换缺陷

> 发现版本：`v0.1.0-beta.10`
>
> 修复版本：`v0.1.0-beta.11`
>
> 状态：已发布；消费端升级到 `@elfui/core@0.1.0-beta.11` 或 `@beta`

## P0：响应式对象和数组整体替换后子组件不更新

Custom Element 的 prop setter 使用 `isState(value)` 判断传入值是否应替换
`__propStates` 中的响应式容器。`isState()` 同时匹配 Ref 和 Reactive，因此
`useRef([]).value`、`useReactive({})` 等响应式代理也会被误当成 Ref 容器。

子组件 effect 已经订阅原有的 `useShallowRef`。直接替换 Map 中的容器不会通知这些
effect，最终形成宿主 property 已更新、子组件 UI 仍保留旧数据的静默错误。

受影响场景包括：

- 父组件整体替换数组或对象，并通过 `.prop` 传给子组件；
- 表格远程排序或重新加载数据；
- VirtualList 从有数据切换为空数组；
- Tree、Transfer、Select 等依赖对象或数组 prop 的组件。

## 修复方案

prop setter 只允许真正的 Ref 替换容器：

```ts
if (isRef(value)) {
  this.__propStates.set(key, value);
  return;
}
```

Reactive 对象、数组和只读代理均作为普通 prop 值写入稳定的
`useShallowRef`，从而通知已经订阅该 prop 的子组件 effect。直接传入 Ref 的高级用法
继续保持容器级订阅。

## 回归范围

- `useRef([]).value` 和 `useRef({}).value` 整体替换；
- `useReactive()` 对象整体替换；
- 真正的 Ref 作为 prop 容器时保持联动；
- 普通对象和数组的引用身份不变；
- Kit Table 远程排序与 VirtualList 空态；
- 完整框架、浏览器集成、宿主框架和发布产物门禁。
