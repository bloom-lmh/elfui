# ElfUI v0.1.0-beta.12 命名 Fragment 响应式 Props 缺陷

> 发现版本：`v0.1.0-beta.12`
>
> 修复版本：计划纳入 `v0.1.0-beta.13`
>
> 状态：框架源码已修复并增加回归测试，等待 beta.13 完整验证与发布

## P0：响应式 Props 初始渲染正确，后续更新不刷新

命名 Fragment 的调用点原先会立即计算动态属性并创建普通对象：

```ts
const props = {
  label: readParentStateOnce()
};
```

Fragment 内部的文本、属性等 DOM effect 只能读取这个快照，无法订阅父级 Ref。因此下面的
`label.set("Beta")` 不会更新现有 Fragment DOM：

```ts
const Card = defineFragment<{ label: string }>((props) => `<strong>${props.label}</strong>`);

const label = useRef("Alpha");

export const Example = defineHtml(`
  <Card :label=${label} />
`);
```

已有 `v-for` 测试未发现该问题，是因为列表源整体替换时会重新执行条目渲染，新的 Fragment
节点读取到了新值，但这不代表 Fragment Props 本身具有响应性。

## 修复原则

- Fragment 仍然只是编译期模板切片，不创建组件实例、独立 effect scope 或 Props storage。
- 动态属性使用惰性只读 Props 视图，在 Fragment 自身的 DOM effect 中读取父级表达式。
- `v-bind` 对象整体替换后，Fragment 继续读取最新对象。
- 属性覆盖顺序与模板书写顺序、对象展开语义一致。
- 更新 Props 只刷新精确 DOM binding，不重建 Fragment 节点。
- Fragment 事件 Props 绑定到父级渲染上下文，避免丢失事件处理器作用域。

## 回归范围

- 基础值 Ref 更新。
- 对象 Ref 整体替换。
- `v-bind` 对象整体替换。
- 解构参数与 `props.xxx` 两种 Fragment 写法。
- Fragment DOM 节点身份在更新前后保持不变。
- Fragment 事件 Props 正确调用父级处理器。
- `v-for` 中的命名 Fragment 保持原有 keyed list 行为。
