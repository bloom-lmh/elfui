# ElfUI v0.1.0-beta.14 组件集成边界审计

## 审计结论

| 反馈                                   | 结论                               | 处理                                                           |
| -------------------------------------- | ---------------------------------- | -------------------------------------------------------------- |
| 命名 Fragment 响应式 Props 不稳定      | beta.12 历史缺陷，当前已修复       | 保留属性、对象替换、事件和节点身份回归测试                     |
| `defineExpose` 与 HTMLElement 成员冲突 | 真实 API 风险，但原有 DEV 警告有效 | 新增 `overrideNative` 显式声明；普通命令仍应改名               |
| template ref 调用子组件 expose 不稳定  | 确认 Runtime 生命周期缺陷          | 子组件 setup/mounted 现在先于父组件 mounted 完成               |
| Provider 跨 Shadow DOM                 | open 已支持，closed 缺少回归覆盖   | 补充 closed Shadow Root 与后插入子组件测试                     |
| Provider 跨 Teleport                   | 确认 Runtime 逻辑父链缺陷          | Teleport 保留组件父链、App Provider 并在卸载时清理节点         |
| 旧 `v-for` / 局部变量问题              | 历史缺陷，当前测试通过             | 不增加组件侧兼容代码                                           |
| `defineHtml(variable)` 不支持          | 静态编译设计约束                   | 保持不变，通过条件、列表、slot、Fragment 和组件组合表达动态 UI |

## Provider 协议

- `inject()` 沿组件逻辑父链解析，嵌套 Provider 最近者优先。
- open/closed Shadow Root 不切断组件上下文。
- Teleport 只改变 DOM 位置，不改变组件父级、Provider 或 App 归属。
- 后插入并完成连接的 Custom Element 读取当时可见的 Provider。
- `provide()` 本身在 setup 中注册一次；动态值应传递 Ref 或响应式对象，而不是重复调用 `provide()`。
- App 卸载会移除 Teleport 子树并停止其独立 effect scope。

## `defineExpose` 冲突协议

默认情况下，覆盖 host 已有成员仍会在开发态警告。为了保持既有组件兼容性，框架不会
静默跳过已存在的公开方法。确实需要实现原生表单语义时必须显式声明：

```ts
defineExpose(
  {
    focus: () => input.value?.focus(),
    blur: () => input.value?.blur()
  },
  { overrideNative: ["focus", "blur"] }
);
```

`scrollTo`、`remove`、`click` 等普通命令不建议覆盖；优先使用 `scrollToOption`、
`removeItem`、`triggerAction` 等表达组件语义的名称。

## 验收覆盖

- 命名 Fragment 动态属性与 `v-bind` 对象整体替换。
- 父组件 mounted 中通过 template ref 调用子组件 expose。
- open/closed Shadow Root、后插入组件、嵌套 Provider。
- 响应式 Provider 身份。
- Teleport 中的组件 Provider、App Provider、逻辑父级与卸载清理。
