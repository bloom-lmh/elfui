# ElfUI beta.14 happy-dom 原生控件 DevTools 元数据异常

日期：2026-07-28

状态：已修复，待下一补丁版本发布

## 现象

在 `happy-dom@20.10.6` 中，向原生 `<select>` 写入 DevTools 模板节点 Symbol
元数据时，`Object.defineProperty()` 会抛出 `TypeError: Cannot convert a Symbol value to a number`，导致模板渲染在组件业务逻辑执行前中断。

## 根因

beta.14 把节点自身的非枚举 Symbol 属性作为唯一元数据存储。该实现依赖 DOM
宿主对象完整支持 Symbol property descriptor，不符合“调试能力失败不能影响业务运行”的隔离原则。

## 修复

- 使用挂载在 `globalThis` 上的共享 `WeakMap<Node, Metadata>` 作为权威存储。
- 节点 Symbol 属性仅保留为旧 DevTools 客户端的兼容镜像。
- WeakMap 和兼容镜像写入均为 best-effort，任何异常都不会中断模板渲染。
- 静态模板树克隆改为通过统一读写函数复制元数据。
- closed Shadow Root 调试通道采用相同的共享 WeakMap 与安全镜像策略。
- 生产构建继续剔除所有 DevTools registry、marker 和 helper。

## 验证门槛

- [x] happy-dom 中原生 `select`、`input`、`button`、`option` 可挂载元数据且不抛错。
- [x] DevTools runtime getter 可读取 WeakMap 元数据。
- [x] 克隆后的 `select/option` 树保留模板节点元数据。
- [ ] ElfUI Kit 全量 165 个文件、1334 条测试由组件库线程复验。
