# v0.1.0-beta.20 Optimization Plan

Date: 2026-07-29

## Goal

Improve ElfUI's production bundle size, component and list runtime performance, compiler transform
throughput, and public API stability without weakening the current reactivity, Shadow DOM, form,
lifecycle, or generated-code contracts.

## Baseline

- Real application fixture: 10.04 KB gzip / 9.07 KB Brotli.
- Core public facade: 17.57 KB gzip / 15.86 KB Brotli.
- Runtime public facade: 15.25 KB gzip / 13.83 KB Brotli.
- Reactivity public facade: 5.17 KB gzip / 4.71 KB Brotli.
- Chromium list create 1k: 8.60 ms; list create 10k: 101.50 ms.
- Chromium Shadow component mount 1k: 15.10 ms.
- jsdom keyed-list remove 5k from 10k: 749.50 ms with 5,000 individual removals.

## Confirmed Issues

- Transition and TransitionGroup can wait forever when CSS does not emit an end event.
- TransitionGroup listens only for `transitionend`, performs full-list DOM reattachment, and uses an
  O(n squared) created-item check.
- Production component instances still allocate DevTools IDs, sets, and debug records.
- Reactivity DevTools creates registries and counters at module initialization in production bundles.
- Every custom-element instance installs prop accessors and eagerly allocates pre-mount/pending
  containers.
- Macro usage analysis and macro compilation parse the same TypeScript file separately.
- The public API snapshot detects exported names but not declaration-signature changes.
- The size baseline label is stale and the production DevTools gate does not assert zero debug
  allocation.
- Metadata v1 compatibility exports outlived their documented one-beta window.
- `TransitionGroupOptions.tag` is exposed by the runtime although the runtime cannot use it.

## Implementation Phases

### 1. Animation Correctness

- [x] Introduce one cancellable CSS end detector for transition and animation events.
- [x] Derive a CSS timeout when no explicit duration is provided and keep a narrow safety fallback.
- [x] Apply it to Transition enter/leave and TransitionGroup enter/leave/move.
- [x] Add zero-duration, animation-only, stale-event, and owner-disposal coverage. Reduced-motion
      behavior follows the computed zero-duration path.

### 2. Production Allocation and Bundle Size

- [x] Make component DevTools state development-only and avoid production IDs/sets/debug objects.
- [x] Lazily create reactivity DevTools registries and counters only in development.
- [x] Extend the production boundary gate to reject retained DevTools registries and component IDs.
- [x] Measure bundle attribution and update the size baseline after final implementation.

### 3. Runtime Hot Paths

- [x] Install component prop accessors once per constructor while preserving pre-upgrade values.
- [x] Lazily allocate pre-mount prop values and pending-child queues.
- [x] Give TransitionGroup a same-key fast path, linear created-item tracking, and minimal DOM moves.
- [x] Measure large list removal in Chromium before changing the ordinary keyed-list removal strategy.
- [x] Add component-prop allocation and TransitionGroup reorder cases to the browser benchmark.

### 4. Compiler Throughput

- [x] Parse each Vite macro transform once and pass the parsed source into compilation.
- [x] Preserve the existing public string-based compiler API.
- [x] Add a deterministic 100/1,000-file transform benchmark or focused parse-count regression test.

### 5. API Stability

- [x] Snapshot canonical public declarations, including parameters, return types, generics, overloads,
      and optional properties.
- [x] Add package-surface validation with `publint` and `@arethetypeswrong/cli` when their output is
      deterministic in the release environment.
- [x] Classify stable, experimental, and generated-internal entry points before RC.
- [x] Resolve expired Metadata v1 exports through an explicit deprecation/removal changeset.
- [x] Separate compiler-only TransitionGroup tag semantics from runtime options without an
      unannounced API break.

## Completion Gates

- Animation cleanup completes even when CSS emits no event.
- Production components allocate no DevTools state and production bundles retain no debug registries.
- Same-order TransitionGroup updates do not detach or reinsert stable nodes.
- The Vite macro path creates one TypeScript SourceFile per transformed file.
- Public declaration changes fail CI unless the reviewed API snapshot is updated.
- Final size and browser benchmark figures are recorded with narrow, measured budgets.

## Measured Results

- Real application fixture: 10.13 KB gzip / 9.16 KB Brotli; budget 10.3 / 9.3 KB.
- Core public facade: 18.47 KB gzip / 16.66 KB Brotli; budget 18.8 / 17.0 KB.
- Runtime public facade: 16.14 KB gzip / 14.64 KB Brotli; budget 16.4 / 14.9 KB.
- Reactivity public facade: 5.23 KB gzip / 4.77 KB Brotli; budget 5.4 / 4.9 KB.
- Chromium list create 1k: 8.00 ms; list create 10k: 108.90 ms.
- Chromium list removal from 10k to 5k: 110.80 ms.
- Chromium Shadow component mount 1k: 11.50 ms; prop-heavy component mount 1k: 41.70 ms.
- Chromium TransitionGroup same-key update 1k: 13.30 ms with zero DOM insertions.
- Chromium TransitionGroup reverse 1k: 10.80 ms with 999 necessary DOM insertions.
- Vite macro transform: 100 files in 43.35 ms; 1,000 files in 330.52 ms.
